# M1 编排、规则、DNS 与客户端预设契约

本窗口对应 T-020、T-021、T-022、T-029、T-049，并补验来源、覆盖与依赖展开。任务完成情况及执行证据由逐项验收记录给出；本契约不是 G1 批准记录。

## 资源管理

`/api/v1/routing-profiles`、`/api/v1/rule-sets`、`/api/v1/dns-profiles` 落实既有 OpenAPI 集合 GET/POST 和对象 GET/PATCH/DELETE。资源继续使用稳定 ID、加密不可变修订、目录版本、引用和事务审计。创建返回 201，读取/修改返回 ETag，修改和删除须携带 If-Match。修订冲突为 412，缺少前置条件为 428；未知字段拒绝。列表沿用筛选绑定游标及每页最多 200 项。

路由规则按数组顺序首匹配；不同字段 AND，同字段多个值 OR。域名后缀包含域名本身和点分隔子域。动作只能为显式 direct、reject、具体 Node、两跳 Chain 或不嵌套的 PolicyGroup。final 必填。preserve_domain 不为 IP 规则主动解析域名，resolve_for_ip_rules 使用显式 DNS 方案。规则数组修改为整体替换。

最终原生补验发现 sing-box 1.14.0 的 resolve 动作在 DNS 失败后直接终止连接，无法保持 Xray／Mihomo 的后续域名规则匹配。因此该目标对 `resolve_for_ip_rules` 且含启用 IP 条件（含规则集 CIDR）的组合返回带路由资源 ID、字段及 target 的诊断；不把它改为 preserve_domain。无 IP 条件和 preserve_domain 不受此拒绝影响。用户已单独批准“接受 sing-box 此项限制并记录范围变更”，该限制据此纳入 G1 范围，原生反例和决定保留在 G1 评审记录。

规则集的 API 只接收规范化的 domain/CIDR entries；内容摘要由服务端计算。CIDR 必须为合法且无主机位的 IPv4/IPv6 网络。浏览器文本编辑支持 DOMAIN、DOMAIN-SUFFIX、IP-CIDR、IP-CIDR6 及无歧义的纯域名/网段行；纯域名为 exact。空行和 # 注释不进入 entries，浏览器保留原始行号映射；服务端 `/entries/N` 诊断映射回原文行。原生路由动作、geodata、远程 provider、二进制规则不接受。

来源刷新失败采用已持久化的退避值递增，最高为刷新间隔；成功重置退避。来源与节点仍沿用既有确认、人工覆盖、认证变化递增安全 epoch 的契约。

## DNS 与依赖

DNS 方案包含独立 bootstrap、业务 resolvers、有序域名规则和明确的 final_resolver。引导解析只接受管理员明确选择的 local 或固定 IP UDP；HTTPS 解析器只能引用已声明的 bootstrap。业务解析器支持 local、固定 IP UDP、HTTPS，并显式选择远端解析流量的出口。

bootstrap 数组的第一项用于代理节点地址的引导解析；HTTPS 解析器单独引用自己的 bootstrap_resolver_id。数组不是并行查询或故障回退列表。目标内核不能同时保持这些选择时，编译返回对应字段诊断，不改用系统或公共解析器。

本地 resolver_id 与资源 ID 分开。重复、缺失、错误类型、自环、间接循环及 CIDR 规则集用作 DNS 域名匹配均拒绝。引用校验包含链两跳和策略成员的完整闭包，缺失、跨 scope、停用和显式排除不会成为隐式省略。编辑时保留禁用规则的引用，以免重新启用规则时引用无从追踪。

域名解析结果与业务 HTTP 连通性结论分别记录。管理 API 不联网验证 DNS；编译仅使用冻结输入，原生运行验证使用许可测试夹具。

## 审核预设与补充决定

单工作空间服务初始化幂等创建三个 Linux 文件预设：Xray JSON、sing-box JSON、Mihomo YAML。数据入口固定 SOCKS `127.0.0.1:1080`，DNS 使用 profile，控制 API 默认关闭。预设作为系统提供的不可编辑资源保存，反复启动不产生新修订或目录版本变动。GET 列表不执行初始化写入。

2026-09-10 用户补充批准增加回环控制预设，用于运行时手动选择。保留原三个预设，另增 sing-box `127.0.0.1:17812` 和 Mihomo `127.0.0.1:17813` 控制变体；不自动把关闭控制的既有预设升级为开启。控制预设只用于本机可信管理，不开放任意监听、脚本、文件路径或外部 UI 自动下载。界面须展示是否开启本地控制接口。

审核通过说明结构化预设符合本项目的约束，不等于特定桌面/移动客户端导入已验证。运行时手动选择必须使用有真实支持和验证证据的控制变体；关闭控制的预设返回明确能力诊断。未验证架构和客户端继续保持 unverified。

## 冻结与编译

冻结 IR 增加可选的 routing_profile、dns_profile 根引用；一旦提供，ID、kind、revision、security_epoch 必须与冻结资源一致并加入完整闭包。完整 M1 配置携带对应预设资源；旧 M0 节点/链夹具的独立最小配置仍可读取，但不作为完整编排配置的替代物。

目标策略覆盖采用现有 PolicyOverride 数组的 JSON 形态；Go 内部按策略组 ID 查找，序列化按稳定 ID 排序，拒绝重复组 ID。覆盖只影响该冻结目标的有效策略，不修改原 PolicyGroup、Node 或其他目标。构造器、Spec 和 Target 读取均深复制覆盖参数及资源载荷。

适配器版本推进至 `0.2.0-m1-orchestration`；内核二进制构建 ID、版本、摘要保持已锁定值。路由、DNS、策略及协议分别转为目标类型，无法等价表达的字段带资源 ID、字段路径和目标键拒绝。不能静默省略参数、改变远端协议、替换策略或故障直连。能力状态只根据对应真实执行证据调整。

本窗口提供纯编译/内核验收所需的冻结模型，不实现订阅方案、持久编译批次、发布头、订阅令牌或公开订阅读取。后续 M2 仍需对真正待发布的最终字节实施全目标持久校验和原子发布。

## 验证与状态

新增迁移只追加；OpenAPI、IR Schema、生成类型、SQLC 产物和契约夹具同步。验证覆盖资源修订/引用/审计、域名/CIDR 行号、AND/OR 与首匹配、DNS 出口/循环、目标覆盖、确定性输出、回环控制选路及无绕行反例。最终执行命令、源码状态、环境、实际成功/失败与未执行项按任务归档。
