# M3 系统与保留契约

`GET/PATCH /api/v1/system/settings`、`GET /api/v1/system/overview`、`GET /api/v1/audit-events` 已接入管理会话。设置写入需要 CSRF 和修订 ETag；并发修改返回 412，前端保留草稿。审计仅记录操作、对象、修订、请求编号及变化字段，不记录设置值、原生配置或凭证。

设置默认值沿用需求：连通性 4、吞吐 1、UTC 日预算 1 GiB，任务事件 7 天、测试结果 30 天、审计 180 天、导入 7 天、发布最近 20 个或 90 天。系统设置还提供默认空的私网代理节点 CIDR 白名单（最多 16 个规范 RFC1918 前缀）；它只影响在线测试的代理节点地址，不放宽登记测试目标。部署并发上限是本交付默认资源的 4/1，页面只能在上限内调整。导入字节限制是解码后大小；两层 Base64 的编码边界按其长度推导，解码不静默截断。

资源写入检查节点总数、规则数量和订阅目标数；导入、来源刷新和编译冻结创建时的限额。已冻结的任务不会因后续调整而扩大执行范围。编译检查实际展开的内核出站和规则数量，发布确定性输出路径不读取设置或时间。

概览展示实际资源数量、任务状态、应用读取字节的预算预留/结算及维护时间。它不是用户流量统计；协议开销不包含在应用字节统计中。内核页面读取锁定清单，提供受修订约束的停用；构建总览继续标为未验证，不能代替具体组合的证据。arm64 按用户决定保留未验状态。

历史清理由 API 后台每分钟执行一个有时限的数据库批次，可通过设置暂停。首先清理到期事件、审计和幂等回执，再按完整任务批次、发布引用及资源修订引用处理。未结束任务不失去输入或预留；删除已结算预留不会减少 UTC 桶中已发生的用量。活动发布、回滚来源、当前修订和被引用修订受保护。旧编译批次没有可查询依赖时保守保留相关历史，直到其过期；不猜测加密输入的依赖。

维护函数在固定数据库权限和固定 SQL 内执行，普通运行账号没有历史删除权限。自定义事务标记不能赋予调用者维护函数所有者的身份；正常历史 UPDATE/DELETE/TRUNCATE 仍被拒绝。设置版本继续不可修改，清理只影响符合保留和引用条件的历史。

当此前发布已超过保留期，保留下来的编译输出显示“此前发布已清理，无法比较”；不将缺失的比较证据当作无变化或首次发布。
