# T-056 加密备份与恢复分项证据

`authorization/report.json` 对真实 PostgreSQL 验证授权纪元变化、旧会话/令牌失效、未结束任务终结与预留结算。

`recovery/report.json` 对合成小数据集使用真实 pg_dump/pg_restore/psql，验证 age 加密备份、节点可解密、恢复旧备份不复活权限、旧租约失效、未知用量结算和未执行预留释放。文件截断、非空恢复目标及最终 Schema 检查失败均拒绝提交；最后一项验证恢复和授权重置的事务原子性。

对应运行：`.cache/m3/05ca1342-1c35-453c-8c84-2175fa12d2e6/report.json`。这是命令库和数据库层的 Linux/amd64 分项验收；后续交付 CLI、每日调度和规模演练需要独立证据，T-056 尚未完成。

交付 CLI 的实际容器验证见 [T-054 部署证据](../T-054/summary.md)。该轮真实备份/校验/恢复及恢复后重新执行配置校验通过，小数据集端到端恢复为 19 秒。每日 systemd 调度已实现，规模数据集与完整 RPO/RTO 结论仍待后续演练。

后续 [规模恢复预检](scale-preflight/report.json)使用 10,000 节点、500 条链、200 组订阅的实际数据库。交付 CLI 备份、完整校验、密钥缺失拒绝、隔离恢复、旧会话/监控令牌拒绝及恢复后的三内核校验通过；逐个读取并解密全部 10,707 个当前资源修订，数据计数保持一致。完整恢复流程实测 **28 秒**。该轮容量负载只有 10 秒，不算 20 分钟基线；每日 systemd 实际触发与持续备份健康仍需在安装环境验证。

[systemd 日历检查](timer-calendar.txt)在已授权的 Linux 测试主机只读执行。systemd 257 正确解析每日 UTC 00:00，下一次和后一次触发点相隔 24 小时。没有安装软件、变更服务或运行生产备份；该记录证明日历解析，不冒充实际定时备份触发证据。

[正式规模演练](rpo-rto.json)记录 RTO **27 秒**，所用已验证备份在全部恢复校验完成时的年龄为 **61.212 秒**，因此本轮恢复点损失窗口的上界低于 24 小时。此上界来自备份认证时间和恢复完成时间，不是对日常调度的持续保证；实际定时触发及备份超期告警的安装环境联验仍保留未完成。
