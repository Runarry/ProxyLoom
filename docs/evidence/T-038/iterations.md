# M2 实施期间的失败与修复

失败记录用于说明修复依据，不替代最终通过的验收。

| 情况 | 处理及最终复核 |
| --- | --- |
| 首次发布 generation=0 被正数 Revision 拒绝 | 发布头与请求使用非负 Counter；实际发布事件继续使用正数 Revision。HTTP 契约与浏览器首次发布通过。 |
| 初始自定 512 MiB 地址空间上限导致原生内核校验失败 | 恢复既有已验配置校验预算：1 GiB 地址空间、2 秒终止宽限及原进程限制。最终三内核实际校验通过。原失败见 [记录](iterations/8f7bdbf9-3bfa-4c0d-ace5-b2e468a129d6.json)。 |
| 浏览器测试使用不准确的下拉框与状态文本定位 | 改为实际可访问 combobox 定位，令牌状态单独展示；最终 3 条真实流程通过。原失败见 [记录](iterations/dffa88ce-26ce-46c3-81b2-dd1836932fa8.json)。 |
| stale 用例错误地使用空来源响应 | 空响应按既有失败保护保留上一成功来源，不产生 stale。改为有效来源中移除原节点，并先断言绑定已 stale；旧版继续下载、新编译拒绝、停用和删除阻断均通过。原失败见 [记录](iterations/12f6ae0b-2dff-49f4-9c3b-26a6d775e2d2.json)。 |
| 开发 Compose 仍把 subscriptions 列作预留 404 路由 | 更新为管理接口 401、无效订阅令牌 404、内部接口不挂载；重新构建并完成 37 项烟测。 |
| POSIX 补验容器默认临时挂载不允许执行合成 helper | 仅将该隔离测试容器的临时目录设为可执行；5 项 POSIX 检查通过。没有改变 Runner 或部署的隔离配置。 |

历史通过的 G1 报告仅用于说明既有映射和行为证据；当前 M2 应用、接口、迁移与浏览器流程均使用本窗口新验收。存储恢复测试模拟进程内对象丢失后重新创建 Repository／Queue，不将其描述为生产故障演练；Compose 另有真实 API 重启、数据库断连和恢复检查。
