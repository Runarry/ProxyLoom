# T-045 故障与清理证据

`supervisor-crash/report.json` 和 `output.txt` 记录 Linux/amd64 实际进程测试。监督进程收到 SIGKILL 后，已执行密封内核字节的沙箱子进程收到父进程死亡信号，并由测试进程回收；本轮实测 10 ms。生产启动线程在子进程存续期保持绑定，避免 Linux 将 Go 启动线程退出误判为监督进程死亡。正常取消仍沿用整个进程组的有界 TERM/KILL 和日志回收。

同一轮文件、进程、内存及网络限制和三个锁定内核配置校验通过。该证据对应报告记录的源摘要，不代替后续依赖补丁后的回归。

`durable-restarts/report.json` 的完整 M3 回归已通过。下载开始后的 Runner 重启、控制 API 中断超过租约窗口、PostgreSQL 容器重启均只执行一个 attempt、一次下载请求，终态后活动连接为零。Runner 重启到取消终态为 1,209 ms；API 中断包含故意等待 31 秒的失联窗口，恢复为 31,105 ms；数据库重启后同一次下载完成为 32,736 ms。这些时长不混同于“确认取消到清理”的 ≤5 秒指标。

该轮使用 Go 1.26.8 和 PostgreSQL 17.11，源清单及数据库卷清理通过；同时完成真实备份恢复与四项浏览器验收。先前失败的数据库夹具使用 tmpfs，容器重启会清空数据库，现按需使用独立临时卷并校验所有权后删除；产品 Compose 一直使用持久卷。失败报告保留，没有被改写为通过。
