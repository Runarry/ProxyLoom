# ADR-0006：M0 Review 修复与补验

日期：2026-09-08。关联 T-023、T-040、T-053、T-028。状态：采用本轮用户确认的修复方案，交付评审待定。历史问题见 `docs/reviews/2026-09-08-m0-review.md`。

1. Runner 每次执行拥有独立进程组；清理只向该组发送信号，根进程由对应 `cmd.Wait` 收割，Linux 被收养后代仅按该组等待。不使用进程全局扫描或 `Wait4(-1)` 回收其他任务。Linux subreaper 初始化失败返回错误。
2. 日志通过显式共享管道交给单个读取者，达到日志上限后继续排空。根等待不依赖后代关闭日志句柄；TERM 2 秒、KILL 后另 2 秒的清理期限和日志收尾均有界。错误通过现有 `error` 返回，不改变 Run/Start/ValidateConfig 签名。Windows 保留进程树终止机制。
3. 能力目录的 Load 和 Build/Record 访问器返回深拷贝，含嵌套切片。调用方修改自己的副本不能改写锁定目录或下一次 Load。
4. 链路验收清理幂等并汇总运行、目录和监听错误。测试先清理，再基于最终测试状态写场景报告；取消或超时不豁免额外清理失败。
5. Compose 烟测使用唯一项目名、独立产物目录；启动前检查全部容器状态及网络/卷，查询失败或固定子网重叠时拒绝。仅清理本轮确认拥有的项目；清理失败不能输出成功。

边界：本轮仍为固定可信内核的 M0 原型，不引入 cgroup、专用监督进程或任意用户程序的执行能力。主动脱离启动进程组的进程不属于本组回收承诺，不得用全局收割补救。HTTP API、数据库 Schema、IR、内核版本及原生编译字节不变，`adapter_version` 保持 `0.1.0-m0-native`，能力保持 `unverified`。

验证和状态以 T-028 下本轮补验报告为准；本 ADR 不宣称检查通过、任务 done 或 G0 正式验收。
