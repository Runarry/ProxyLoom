# M2 订阅发布契约

本窗口落实 T-030～T-038、T-050；最终完成状态以 PLAN 和逐项验收证据为准。M2 使用既有单工作空间、可信管理员、锁定构建、类型化 IR、持久队列与独立 mTLS Runner。网络连通性、测速与生产运维仍属于 M3。

## 订阅与冻结

订阅成为 `subscription_profile` 类型化资源，使用既有加密不可变修订、引用、审计、ETag 和 If-Match。复制接口 `POST /subscriptions/{id}/clone` 接收新名称，创建新的方案身份，保留原节点和编排引用，不复制发布或令牌。

基础成员为 `(include_ids ∪ 标签匹配) − exclude_ids`。本次用户确认：标签条件全部为空时不额外选取资源。非空 selector 的 all_tags 要求全部命中，any_tags 非空时要求至少一项命中，none_tags 要求全部不命中。匹配范围为节点、链和策略组。标签匹配跳过不可用成员；显式选择、必要依赖中的不可用资源报错。链、策略、路由、DNS 和预设组成完整依赖闭包；排除必要依赖报错。

固定预设继续限制监听端口和控制接口。client_parameters 仅接受与已审核预设相符的有效值，在冻结时再次核实，不忽略不相容覆盖。connectivity_gate 保留为后续契约，本窗口明确拒绝启用。

新增迁移 000015，不修改既有已提交迁移。编译批次在短 REPEATABLE READ 事务内绑定方案修订、目录版本、认证 epoch、完整依赖、各资源安全 epoch、构建摘要、适配器版本、预设修订和目标覆盖。保存加密冻结载荷与编译任务后释放事务。编译不读取活动资源、网络或当前时间。批次、令牌及发布事件不推进 catalog_revision；配置编辑推进目录版本，使未发布批次过期。

## 编译、校验与预览

API Worker 执行 compile；Runner 只执行对应最终字节的 config_validate。产物加密入库与校验任务创建原子提交，按批次和目标唯一约束；复用现有租约、fencing、幂等结果及配置校验预算。运行失败给出固定、脱敏的诊断。服务端从持久任务状态汇总批次，重启后继续恢复，不依赖进程内通知。

批次保持 queued／compiling／validating／ready／failed／obsolete。只有全部启用目标成功校验才能 ready。阻塞原因另行呈现；Runner 未完成校验时继续等待，不把离线或无结论视作通过。

每个目标的新旧文本预览各最多展示 32 KiB，截断状态显式提示；完整依赖仍展示，差异标记和确认摘要始终覆盖完整产物。输出诊断最多展示 50 项、批次诊断最多 200 项，超出时有明确提示。

完整输出经过监听、控制接口、文件与下载等最终检查。结构化脱敏预览与真实产物分离；差异标记基于完整内容 HMAC，因此被脱敏的凭证变化也会显示内容变化。effective_preview_hash 绑定确切批次、冻结输入、各目标内容和比较基准。读取预览时登记当前认证操作者看到的摘要；发布必须同时匹配登记与明确确认，客户端不能指定操作者身份。

宽泛能力目录仍为 unverified。发布资格使用带具体构建、映射版本和参数约束的独立证据；本批最终字节还必须经过实际内核检查。linux/amd64 之外的架构、桌面／移动客户端导入和任意远端互通不因此升级。链路行为的既有证据限定在 Trojan TCP/TLS 两跳；其他组合须补对应真实链路证据。VMess 加密参数的补充配置校验以 T-030 的 M2 原生矩阵记录为准。sing-box 已批准的 DNS／IP 解析限制继续明确拒绝，不自动改写配置。

## 发布、回滚与撤销

POST publish 保留方案 If-Match，并使用独立 expected_generation 比较发布头；首次 generation 为十进制字符串 `0`。服务端重查目录、依赖安全状态、构建启停、确认及全部目标结果，在短事务内一次切换整批发布。失败保留仍安全的旧发布，不拼接不同批次的目标。

回滚复用历史固定产物、生成新的发布事件，重新检查安全 epoch、构建与当前目标授权。普通改名不改变旧字节；停用、删除或凭证轮换阻断受影响历史产物。stale 默认不进入新发布，但其本身不阻断仍安全的旧发布。

内核列表和停用接口使用已锁定身份。首次登记不覆盖已有记录，重启不重新启用停用构建。完整内核管理页面仍属于 T-052。

## 令牌与下载

令牌只在首次签发响应中返回原值；数据库保存带用途区分的 HMAC 校验值、方案、目标范围、有效期和 auth_epoch。签发需近期重认证；撤销使用令牌自身的 If-Match。幂等重放只返回元数据，首次响应丢失后应撤销并重签。轮换由签发新令牌和撤销旧令牌组成；撤销失败时界面明确保留待处理状态。

GET `/s/{token}/{target_key}` 在主库当前快照中检查令牌、方案、目标和发布依赖，只读取保存的产物字节；不重建编译输入，也不刷新、编译、校验或测速。首版不增加配置缓存。返回 private, no-store 和 nosniff，访问日志使用模板路径。无效、过期、撤销或无目标权限统一 404；无安全发布或数据库不可用返回 503，不返回空配置或直连配置。

撤销提交后开始的新请求必须被拒绝；已完成授权并正在传输的响应以及客户端下载副本不承诺撤回。完整配置导出复用近期认证和敏感审计；默认预览不会包含原凭证。

## 验证入口

- `node scripts/verify-m2.mjs postgres`：独立 PostgreSQL 的订阅、批次、发布、回滚、令牌及 HTTP 契约专项；模拟结果仅用于事务测试，不算真实内核证据。
- `node scripts/verify-m2.mjs native`：Linux 容器内真实 mTLS、Worker、三个锁定内核、完整发布与字节一致性。
- `node scripts/verify-m2.mjs browser`：生产前端、真实 API／数据库／Worker／mTLS Runner／内核，由隔离浏览器验证操作流程。
- `node scripts/verify-m2.mjs all`：顺序执行以上专项。测试资源按专属标识创建并清理，报告与运行附件位于 `.cache/m2/<run_id>/`。

还需运行现有完整质量入口、Compose 烟测和适用回归。只有最终稳定源码的证据才能用于 G2 收口；早期失败和未执行范围须明确保留。
