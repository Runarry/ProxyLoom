# 1. 项目背景与目标

## 1.1 项目定位

建设一个可自托管的多内核订阅管理后台，以统一节点模型管理连接信息，以配置编译器分别生成 Xray、sing-box、Mihomo 配置，并利用内置内核进行配置校验、真实代理连通性测试和受控测速。系统是配置与测试的管理平台，不是默认承载用户日常代理流量的网关。

平台需要覆盖节点输入、配置编排、兼容性检查、发布、订阅获取、测试和运维的完整流程。管理员不必为三个内核重复维护三套节点，但仍可以为特定内核配置明确的差异化行为。

## 1.2 原始诉求与交付映射

| 原始诉求 | 对应能力 | 核心需求编号 |
| --- | --- | --- |
| 导入分享链接、支持协议转换 | 链接解析、统一模型、按能力转换配置格式 | FR-003～FR-007、FR-010～FR-011 |
| 手动配置节点 | 类型化节点表单、服务端校验、版本历史 | FR-008～FR-009 |
| 两个节点组成链式代理 | 有序两跳链、方向展示、引用校验、独立测试 | FR-012～FR-014、FR-029 |
| 分流、负载均衡及其他内核能力 | 策略组、路由、DNS、规则集、受控扩展 | FR-015～FR-020 |
| 多组独立订阅 | 节点筛选、依赖展开、目标配置、令牌和版本发布 | FR-021～FR-026 |
| 内置三个内核测试和测速 | 构建管理、配置校验、连通性、吞吐与任务中心 | FR-027～FR-032 |
| 前后端分离、Docker、Go 后端 | 管理界面、API 契约、Go 服务、容器与备份 | FR-033～FR-040 |

## 1.3 成功标准

管理员能够导入或创建节点，建立 A→B 两跳链，配置策略组与路由，在至少两组订阅中选择不同成员，针对声明支持的三内核目标完成预览、校验和发布。真实内核测试必须能够区分配置错误、远端连接失败及测试基础设施故障。订阅撤销和节点安全停用必须阻止后续获取受影响配置。

“成功导出一个文件”不是最终成功标准。发布物还必须保留已声明支持的连接语义，包含全部依赖，能够被对应内核加载，并在受控测试环境中通过相应行为测试。

# 2. 基线假设、边界与术语

## 2.1 本期默认假设

| 项目 | 本期默认值 | 后续调整方式 |
| --- | --- | --- |
| 使用形态 | 自托管，单工作空间，可信管理员 | 多租户另行立项，不把预留字段当成已实现隔离 |
| 管理账户 | 至少一个管理员；无开放注册 | 多用户协作和细粒度角色列入 P1 |
| 部署平台 | Linux Docker，发布 amd64 和 arm64 镜像 | 不把 Windows/macOS 原生服务部署作为本期门槛 |
| 后端语言 | Go；独立内核二进制由 Runner 执行 | 不将三个内核源码直接嵌入业务进程 |
| 数据库 | PostgreSQL | SQLite 单文件版不在本期双轨维护 |
| 主要产物 | 三内核完整配置；附加 URI/Base64 节点输出 | 节点集合输出不得承诺保留复杂编排 |
| 链式代理 | 两跳、两端均为具体节点 | 数据模型预留多跳，但本期拒绝三跳及策略组作为链跳 |
| 发布策略 | 严格检查、显式发布、不静默降级 | 自动发布须另行配置并遵守相同检查 |
| 测试范围 | 配置、代理 HTTP(S) 连通性、受控下载测速 | 上传、UDP 专项测试及多地 Agent 为 P1 |

## 2.2 必须区分的概念

**配置格式转换与实际协议转换。** 本系统将同一远端连接的信息转为目标内核可理解的配置，不会把只提供 VLESS 的远端服务变成 Trojan 服务。真正改变远端通信协议需要服务端配合或新增网关，不在本期范围。

**节点订阅与完整配置订阅。** 前者只表达单节点；后者可以包含链、策略组、路由、DNS 和本地入口。普通分享链接不能被当成复杂编排的通用载体。Shadowsocks 的 SIP002 也是特定协议的 URI 方案，而不是跨内核完整配置标准。[R15]

**配置加载与客户端导入。** 内核校验通过，不等于每个使用该内核的桌面或移动客户端都接受相同订阅格式。平台必须独立标记内核验证状态和客户端导入验证状态。

**自动选优与负载均衡。** sing-box 提供 selector、urltest；Mihomo 提供独立的 load-balance 策略组。低延迟选优不等于按连接分摊流量，不允许静默互换。[R06][R07][R12]

## 2.3 术语表

| 术语 | 本项目含义 |
| --- | --- |
| Node／节点 | 一条可连接的远端代理服务记录，不携带自身的链依赖 |
| Source／来源 | 导入文本、文件或远程订阅，以及其刷新与解析记录 |
| Chain／代理链 | 从客户端到最终出口的有序节点列表；A→B 中 B 为出口 |
| PolicyGroup／策略组 | 客户端运行时选择或分配出口的配置对象 |
| SubscriptionProfile／订阅方案 | 确定发给订阅用户的成员、路由、DNS 和输出目标 |
| Target／输出目标 | 内核构建、客户端预设、格式和显式策略覆盖的组合 |
| IR／中间模型 | 不依附某个内核原生字段的统一、类型化配置表达 |
| Revision／修订版 | 某个业务对象不可变的历史版本 |
| Publication／发布版本 | 固化依赖、编译并校验通过的一组不可变目标产物 |
| Runner／执行器 | 领取任务，运行内核及测试，将结果回传的独立 Go 服务 |
| 能力清单 | 经指定版本及测试验证的协议、参数、策略与平台组合 |

# 3. 范围、优先级与能力承诺

## 3.1 优先级定义

P0 为基础上线必须具备的闭环能力；P1 为后续增强，但本文件提前定义其扩展边界；P2 为明确暂不实现的探索能力。需求中列出的 P1 子项不属于 P0 验收范围。

P0 必须完整覆盖用户提出的七项诉求，但“其他内核功能”按已定义的能力清单实现，不等同于支持每个内核所有配置项。

## 3.2 协议与输入范围

| 类别 | P0 范围 | P1 范围或约束 |
| --- | --- | --- |
| 通用节点 | Shadowsocks 常用 AEAD、VMess AEAD、VLESS、Trojan、SOCKS5、HTTP CONNECT | 旧加密、插件、非常用字段需单独适配，不默认透传 |
| 传输及安全 | 经验证的原生 TCP、WebSocket、TLS；VLESS REALITY 独立组合验证 | gRPC、HTTPUpgrade、XHTTP、复用等逐项纳入清单 |
| 特定协议 | 不以三个内核交集限制数据存储 | Hysteria2、TUIC、AnyTLS、WireGuard 等按目标适配 |
| 输入 | 单条 URI、批量 URI、Base64 列表、上述格式的远程订阅 | 原生 JSON/YAML 仅提取明确支持的节点字段 |
| 输出 | 完整 Xray JSON、sing-box JSON、Mihomo YAML；URI 与 Base64 | Mihomo provider、外部规则附件等按客户端预设增加 |

此表是产品实施范围，不是对上游能力的穷举。例如当前 Xray 官方文档已经列出 Hysteria version 2，因此不能把“Xray 永不支持 Hysteria2”写成固定规则；是否启用仍须验证项目锁定构建。[R25]

## 3.3 不在本期范围

不建设远端代理服务端开通平台、支付计费系统、机场用户流量计费、客户端应用、长期代理网关、任意协议转换网关或跨内核多进程桥接。不得把内置测速产生的字节数展示成最终用户订阅用量。未经额外安全设计，不允许不可信公众提交节点并执行任意网络测试。

# 4. 参与者与业务流程

## 4.1 参与者与权限

| 参与者 | 允许行为 | 明确限制 |
| --- | --- | --- |
| 管理员 | 管理节点、链、策略、订阅、令牌、测试和系统参数 | 敏感导出、恢复、密钥轮换需再次验证身份 |
| 订阅使用者 | 持指定令牌获取指定方案的获准输出目标 | 不能访问管理 API、其他方案和来源凭证 |
| Runner | 领取分配任务，读取任务必要配置，回传状态与结果 | 不持有数据库连接、全局主密钥和完整节点库 |
| 运维人员 | 配置部署、TLS、备份、镜像升级及网络隔离 | 主机权限属于另一个信任边界，不等同于应用内角色 |
| 只读／编辑人员（P1） | 按角色读取脱敏数据或编辑草稿 | 无默认凭证导出、令牌签发、发布与系统管理权限 |

P0 的全部管理操作由管理员执行；P1 角色仅为设计预留，不能以表中列出角色宣称多用户授权已经完成。

## 4.2 典型业务流程

**首次使用：** 配置 Docker 与密钥文件 → 初始化管理员 → 检查三个内核构建 → 创建测试目标 → 导入节点 → 建立首个订阅方案 → 校验、发布 → 生成访问令牌。

**节点编排：** 选择 A 和 B → 界面展示“客户端→A（第一跳）→B（最终出口）→目标” → 校验连接承载能力及依赖 → 保存独立 Chain → 测试整条链 → 加入订阅成员或策略组。

**来源更新：** 拉取来源 → 限额与安全检查 → 解析为候选变更 → 与来源身份匹配 → 应用人工覆盖 → 展示新增、修改、失效和冲突 → 提交修订 → 标记相关订阅待重新编译。

**订阅发布：** 选择成员和输出目标 → 展开依赖 → 冻结修订与规则版本 → 兼容检查 → 编译 → 对目标内核执行配置检查 → 发布预检 → 原子切换版本 → 客户端拉取。

**安全撤销：** 撤销令牌，或停用被泄漏节点 → 提交安全状态 → 后续拉取立即经过新的权限检查 → 受影响发布物被拒绝返回 → 管理员替换节点并重新发布。

# 5. 功能需求

## 5.1 账户、导入与节点管理

### FR-001 初始化与认证（P0）

系统必须提供一次性管理员初始化、登录、退出、会话过期和管理员凭证重置流程。默认无公共注册入口，不能包含固定默认密码。

验收：完成初始化后，初始化入口不可被再次利用；未登录请求管理接口失败；退出和密码重置可使相应会话失效。重置只能通过已授权管理操作或受控主机命令执行。

### FR-002 权限与敏感操作（P0，协作角色 P1）

管理 API、订阅 API、Runner API 使用独立凭证与权限边界。凭证查看、完整配置导出、令牌签发、恢复和密钥操作必须被审计；高风险操作要求近期重新认证。

验收：订阅令牌不能调用管理接口；Runner 凭证不能枚举节点；普通列表不返回密码、UUID 等认证内容。P1 新角色必须通过独立授权测试后开放。

### FR-003 单条与批量分享链接导入（P0）

支持粘贴单条或多条链接。系统逐条识别协议和链接方言，保留来源位置，显示成功、重复、错误及不支持项。未知参数保留为隔离的原始元数据，不进入可执行配置。

验收：混合合法与错误输入时展示逐行结果；未确认前不修改正式节点库；确认后仅提交勾选且有效的候选项。缺失必填字段不得用伪造默认值补齐。

### FR-004 文件与格式识别（P0，原生配置提取 P1）

支持 UTF-8 文本文件、URI 列表及 Base64 列表。自动识别必须可以被用户指定的格式覆盖，必须限制解码层数、文件大小和条目数。

验收：非法 Base64、压缩膨胀、重复键或超限输入返回明确错误；不会无限递归解析。P1 原生 JSON/YAML 仅导入白名单字段，不导入监听器、脚本、文件路径或执行参数。

### FR-005 远程来源与刷新（P0）

支持 HTTPS 来源地址、手动刷新、周期刷新、最近成功时间及错误记录。HTTP 默认关闭，可由管理员针对来源明确启用。来源请求头属于敏感配置。

验收：刷新失败或返回无法解析内容时保留最近成功数据；同一来源同时只有一个有效刷新提交；重定向、DNS 地址及返回大小均受安全检查。周期任务不能因服务重启而永久丢失。

### FR-006 节点身份与去重（P0）

节点具有不随名称、地址或凭证改变的稳定 ID。内容指纹仅用于重复检测，不作为唯一身份。来源没有可靠身份时，系统只能提出匹配建议，不能静默把两个不同节点合并。

验收：重命名不破坏代理链引用；明确匹配的凭证变更产生新修订；模糊匹配进入待确认状态；手动复制产生新的节点 ID。

### FR-007 来源记录与人工覆盖（P0）

来源原始数据和人工覆盖分别保存，最终节点由当前来源记录叠加显式覆盖得到。覆盖项可以逐字段撤销。来源失效节点进入 stale 状态，不能被当成确认删除。

验收：刷新改变地址时不会覆盖用户自定义名称；覆盖字段有标记；“恢复来源值”可得到当前来源数据；来源恢复后可重新识别原节点。

### FR-008 手动创建和编辑节点（P0）

按协议展示基本信息、认证、传输、安全及高级字段。服务器地址、端口、协议、认证字段和组合关系由后端校验。保存生成新修订并支持并发冲突检测。

验收：非法端口、无效凭证形态、不相容传输组合不能保存为可用节点；遮罩占位符不能被误写为密码；过期版本的更新返回冲突，不覆盖他人修改。

### FR-009 节点检索与生命周期（P0）

支持分页、搜索、标签筛选、批量标记、启用、停用、克隆、软删除和引用影响查看。默认不永久删除被历史发布或测试引用的修订。

验收：停用或软删除阻止新编译，并阻止后续下载含该资源的旧发布物；普通重命名不改变稳定 ID。凭证变更按安全变更处理，旧发布物不得继续被返回。

## 5.2 转换、代理链和策略

### FR-010 兼容检查（P0）

针对“内核构建＋协议参数＋传输＋安全选项＋平台＋客户端预设”给出 verified、conditional、unsupported 或 unverified。界面必须说明原因及定位到字段。

验收：只有 verified，或条件已经满足且验证通过的组合可发布；未验证不得显示为“已支持”。任何被忽略的关键字段必须产生错误，不能只写日志。

### FR-011 配置转换与节点导出（P0）

将统一模型转换为目标内核配置，或将可独立表达的节点输出为 URI/Base64。系统必须给出结构差异、丢失字段和不兼容说明。

验收：转换不改变协议和凭证语义；请求把含链、策略、路由的方案转为 URI 时拒绝，除非用户明确执行独立的“仅导出原始节点”操作；后者必须提示编排不被保留。

### FR-012 创建有序两跳链（P0）

管理员可选择两个已存在的具体节点构成 Chain，明确第一跳和最终出口；交换顺序视为不同配置。链是独立对象，不能通过修改原节点实现。

验收：A→B、B→A 的展示和导出方向不同；原 A、B 的独立配置不变；同一节点可以被多个 Chain 引用。

### FR-013 链式依赖和承载校验（P0）

校验节点存在且可用、没有重复自引用、没有循环、没有超长链，并检查前一跳是否可以承载后一跳所需的传输。P0 不接受策略组作为链跳。

验收：缺失节点、A→A、三跳、无法承载 UDP 的组合被拒绝；仅凭两个节点分别连通不得把整条链标为通过。

### FR-014 链式输出、复用与失败处理（P0）

三个适配器按各自原生拨号代理机制生成独立链实例。业务流量交给末跳；末跳连接经前一跳建立。三内核机制分别为 Xray dialerProxy、sing-box detour、Mihomo dialer-proxy。[R01][R05][R11]

验收：同一出口节点用于两条链时不串链；链故障不退化成直连、单跳或未授权出口；发布物包含链中所有必要依赖，并提示接收者能够获得链内凭证。

### FR-015 基本策略组（P0）

统一模型支持固定出口 fixed、客户端手动选择 manual_select 和自动低延迟选优 latency_best。目标内核无法原生表达时，应报错或由管理员明确配置该目标的另一策略。

验收：运行时手动选择不能被静默变成发布时固定选择；成员为空、默认成员不在组内、组嵌套循环都必须被拒绝。P0 组成员仅允许节点和链，禁止组嵌套。

### FR-016 负载均衡与故障策略（P0，扩展策略 P1）

提供 round_robin，针对验证通过的 Xray/Mihomo 目标实现；其他目标不能以 urltest 冒充。consistent_hash、sticky 和特定 fallback 策略作为按内核开放的 P1 能力。[R03][R06][R12]

验收：在受控环境发起多条独立连接可观察到声明的分配行为；全部成员失效时不得绕过策略直接联网。每个目标的覆盖配置和差异必须在发布报告中可见。

## 5.3 分流、DNS 与客户端方案

### FR-017 有序分流规则（P0）

支持完整域名、域名后缀、目标 IP 网段、目标端口和 TCP/UDP 匹配；动作支持直连、拒绝、指定节点、链或策略组。必须显式配置默认出口。

验收：规则顺序在三种输出中保持一致；同一规则不同字段按 AND、同字段多个值按 OR 解释；无法等价表达时阻止发布。域名与 IP 匹配的解析行为由 DNS 方案显式决定。

### FR-018 规则集管理（P0，远程和二进制格式 P1）

P0 支持手动维护域名及 CIDR 文本规则集，导出时内联并固定修订。P1 可增加远程刷新和内核专用规则格式，必须固定内容摘要和转换版本。

验收：非法 CIDR 和含混语法有行号错误；受影响订阅可追溯规则修订；规则变化不会修改已发布字节；不识别的二进制规则不能假装已经跨格式转换。

### FR-019 独立 DNS 方案（P0）

分别配置代理服务器域名的引导解析、业务域名解析、解析服务器及出口选择。P0 提供版本验证过的本地／指定 UDP／HTTPS 解析预设和基本域名 DNS 规则；复杂 FakeIP、平台特例为 P1。

验收：能检测“连接代理需 DNS，而该 DNS 又依赖同一代理”的闭环；不会隐式使用管理员未选择的解析服务；DNS 验证状态与业务 HTTP 连通性状态分别展示。[R01][R09]

### FR-020 客户端预设和高级扩展（P0，原生扩展编辑 P1）

预设定义输出格式、本地监听、DNS、平台要求、控制 API 与导入方式。P0 只开放经过审核的结构化预设；P1 原生扩展必须受字段白名单约束，且仅对相应内核生效。

验收：客户端未验证时展示“仅验证内核加载”；未经允许的监听地址、脚本、任意文件和自动下载功能不能通过扩展注入测试配置；平台生成的依赖标签不能被覆盖。

## 5.4 订阅生成与发布

### FR-021 多组订阅方案（P0）

支持创建多组相互独立的订阅方案。每组选择名称、成员、路由、DNS、客户端目标及发布策略，可以复制方案但不复制节点身份。

验收：至少两组使用不同成员并产生不同内容；修改其中一组不会改变另一组的发布版本；每组可分别启用或停用。

### FR-022 成员筛选与依赖展开（P0）

支持手动包含、手动排除和标签条件选择；规则为“显式包含与筛选结果取并集，再减去显式排除”。编译后自动补齐链、策略组和路由引用的依赖。

验收：路由引用的出口不能遗漏；显式排除与必要依赖冲突时必须报错；自动依赖单独展示，用户在发布前确认其凭证将被包含。禁用、删除或 stale 节点默认不进入新发布。

### FR-023 编译预览与差异报告（P0）

编译必须先冻结全部输入，再生成脱敏预览、兼容诊断、依赖清单、目标差异和内容摘要。完整含凭证配置仅供已授权的敏感导出。

验收：相同冻结输入、适配器和目标得到相同明文字节；不同编译产生的加密随机数不影响内容摘要；错误有资源 ID、字段路径和修复提示。

### FR-024 原子发布与回滚（P0）

默认一个方案中所有启用目标通过检查后一起发布。编译或校验失败保留上一有效版本；发布期间依赖发生变化则该编译结果过期，不允许抢先覆盖新编辑。

验收：并发拉取只能看到完整旧版本或完整新版本；回滚生成新的发布事件并重新检查当前安全状态；历史版本含停用节点、旧凭证或被禁用内核时不能回滚生效。

### FR-025 订阅访问令牌（P0）

一组订阅可签发多个独立令牌，每个令牌限制输出目标、有效期和状态。原始令牌只在签发时展示，支持撤销和轮换。

验收：令牌不可用于其他方案；撤销提交之后开始的请求不得返回配置字节；过期、无效和无权限请求不能泄漏方案信息。明确提示令牌撤销无法使已经下载的节点凭证失效。

### FR-026 订阅获取（P0）

订阅请求只读取有效发布快照，不在请求内拉取上游、编译、校验或测速。下载前必须重新验证令牌和发布依赖的当前安全状态。

验收：无有效版本返回明确的非成功响应，不返回空配置或默认直连配置；缓存不得绕过撤销检查；链和规则变化只通过新发布版本生效；后台测速流量不能作为订阅用户流量头返回。

## 5.5 内核与测试

### FR-027 内核构建管理（P0）

Runner 镜像内置三个经过登记的二进制，记录版本、架构、构建特性、摘要和适配器版本。支持构建停用和版本回退，禁止生产启动时自动追踪 latest。

验收：运行版本与登记不一致时拒绝接单；不可执行架构、缺失依赖或不支持的构建特性有明确诊断。上游编译标签会影响功能，不能只保存版本字符串。[R10]

### FR-028 原生配置校验（P0）

对编译生成的最终目标配置调用对应内核的检查模式，在受限环境记录退出码、结构化错误和脱敏日志。[R04][R08][R14]

验收：三个内核各有有效与无效配置测试；校验失败阻止发布；成功仅表示配置被接受，不自动标记节点连通；完整客户端配置检查与最小探测配置检查不能混为一谈。

### FR-029 真实代理连通性（P0，UDP 专项 P1）

由指定内核运行只监听本地的测试入口，测试程序通过该入口访问管理员登记的受控 HTTP(S) 目标。支持单节点与完整两跳链。

验收：记录对象修订、内核构建、Runner 位置、目标、时间和错误阶段；不以 ICMP Ping 替代代理测试；响应状态或内容不符合预期时不能判成功。生产测试的出口 IP 只作诊断，不单独证明整条链。

### FR-030 下载测速与流量预算（P0，上传 P1）

支持以时间和字节双重上限进行下载测试；明确显示样本是否被限制、缓存是否关闭以及吞吐单位。默认建议每个样本最多 10 秒或 20 MiB，先达到者停止。

验收：读到字节上限立即停止；失败、取消和丢失任务也计入实际或保守预算；吞吐只使用有效读取字节及对应持续时间计算，不能把少量首包样本包装成线路带宽。

### FR-031 测试任务控制（P0）

支持批量创建、排队、取消、超时、重试限制、任务租约和崩溃恢复。配置错误不自动重试；吞吐任务默认不自动重试，以防重复消耗流量。

验收：重复提交不会重复创建相同任务；Runner 失联后旧租约结果无法覆盖新结果；取消后内核进程、端口和临时配置被回收；重启不会遗留永久 running 状态。

### FR-032 测试结果和历史（P0）

展示配置、连通性及吞吐的独立状态，支持按对象、内核、日期和测试位置筛选。节点修订后旧测试标为历史，不继续显示“当前已通过”。

验收：比较时提示目标、时间窗口和执行位置差异；显示成功率及有效样本数；样本不足时不展示有误导性的 P95。后台结果明确标注为 Runner 网络视角。

## 5.6 管理界面、运维和交付

### FR-033 管理界面与任务中心（P0）

提供概览、节点、来源、代理链、策略组、路由与 DNS、订阅、任务、内核和系统设置页面。通过事件流显示任务进度，刷新页面可恢复任务状态。

验收：失败状态可跳转到具体对象；重连不会把同一事件重复累加；长列表分页；正在编辑的草稿不会因任务进度更新被覆盖。

### FR-034 审计与敏感数据保护（P0）

节点认证信息、来源凭证、原始导入内容和发布产物需要加密存储。审计记录操作者、对象、动作、结果和变更摘要，不保存明文秘密。

验收：数据库备份和常规日志中不出现明文密码、令牌、完整分享链接；管理员密码使用专用密码哈希而非可逆加密；测试日志经过截断与脱敏。[R17][R18]

### FR-035 备份与恢复（P0）

支持数据库及必需配置的备份恢复说明、主密钥单独保管和定期恢复演练。历史任务恢复后不得无条件重新执行。

验收：在干净环境完成恢复后能解密节点并读取有效发布物；缺失密钥必须明确失败，不生成替代密钥；恢复默认吊销全部旧会话、Runner 凭证和订阅令牌，防止旧备份复活已撤销权限。

### FR-036 Docker 部署与运维（P0）

提供前后端分离代码、Dockerfile、Compose、环境配置样例、健康检查、迁移流程、持久卷及升级回滚文档。普通测试不需要特权模式、Docker Socket 或 TUN 设备。

验收：空环境可按说明初始化，重启数据不丢失；数据库和 Runner 不暴露公网端口；三个内核不会成为公共开放代理；API 不具备任意执行内核命令的公共入口。[R20][R21]

### FR-037 配额与保留策略（P0）

管理员可配置输入大小、节点数、规则数、编译展开上限、任务并发、流量预算、超时和历史保留。超过限额应在可预测阶段失败。

验收：批量操作不能绕过单次和每日预算；全部计数有一致单位；清理历史不会删除活动发布、引用中的修订和未结束任务必需的数据。

### FR-038 API 契约与错误模型（P0）

交付机器可读 OpenAPI、统一错误码、分页、幂等键、乐观并发和事件模型。API 以版本化路径提供，业务字段采用稳定命名。

验收：前后端依据同一契约生成或验证类型；未识别字段默认拒绝；错误区分输入、兼容、冲突、权限、容量和执行失败，不以一律 HTTP 500 代替业务诊断。

### FR-039 可用性与语言（P0）

界面以简体中文为默认，保存统一 UTC 时间并按浏览器时区展示。链方向、测速单位、不可逆操作和敏感数据导出有清晰文字说明。

验收：关键操作可通过键盘完成；错误不能仅靠颜色表达；移动端能查看任务和复制订阅地址，复杂编排以桌面界面为主要验收场景。

### FR-040 兼容基线与版本升级（P0）

每个宣称支持的组合必须关联样例和测试记录；升级内核、适配器、规则转换器或模板时触发回归。未通过的组合保留为 unverified 或 unsupported。

验收：发布清单包含三内核版本和摘要、构建标签、目标客户端状态、协议参数样例及已知限制；没有实际运行验证的功能不标记为“已验证”。

# 6. 核心业务规则与状态

## 6.1 不可破坏的业务规则

| 编号 | 规则 |
| --- | --- |
| BR-01 | 节点名称不是身份；所有内部引用使用稳定 ID。 |
| BR-02 | Chain 保存节点顺序，不修改原 Node；末跳为业务出口。 |
| BR-03 | 三内核必须分别编译，不用某个内核的原生 JSON 充当唯一数据模型。 |
| BR-04 | 未支持的协议、传输、DNS 或策略不得静默替换或丢弃。 |
| BR-05 | 策略组选择属于客户端运行时行为，后台测试不会控制已分发客户端。 |
| BR-06 | 显式排除优先于显式包含；必要依赖被排除时整次编译报错。 |
| BR-07 | 空策略组、空默认出口、缺少链依赖和 DNS 循环禁止发布。 |
| BR-08 | 发布快照不可变；变更节点、规则、模板必须产生新修订和新发布。 |
| BR-09 | 普通编辑不改旧发布字节；停用、删除、凭证轮换和安全撤销阻断旧发布获取。 |
| BR-10 | 返回旧发布只限其仍通过当前授权与安全检查的情况。 |
| BR-11 | 链、策略或测试失败不得自动直连；显式路由的直连不受此限制。 |
| BR-12 | 后台测速结果不代表客户端网络，也不代表真实线路最大带宽。 |
| BR-13 | 已下载的节点凭证无法被订阅系统远程收回，必须在远端轮换。 |
| BR-14 | 订阅获取不触发网络探测、来源刷新或配置编译。 |
| BR-15 | 原生扩展受白名单约束，不能覆盖安全边界、标签和引用。 |
| BR-16 | scope 预留和子进程分离不构成已实现的多租户安全保证。 |

## 6.2 主要状态定义

| 对象 | 状态 | 业务含义 |
| --- | --- | --- |
| 节点有效性 | enabled／disabled／deleted | 管理员控制；与测试成功失败分离 |
| 来源状态 | active／stale／conflict | 上游可见性与匹配情况，不等同于连接健康 |
| 能力诊断 | verified／conditional／unsupported／unverified | 是否存在已验证实现及满足的前置条件 |
| 编译批次 | queued／running／ready／failed／obsolete | obsolete 表示输入已变化，结果不可发布 |
| 发布物 | published／superseded／blocked | blocked 阻止获取；superseded 可用于受控回滚 |
| 任务执行 | queued／leased／running／succeeded／failed／canceled／timed_out | 表示执行状态；目标失败另由 verdict 表示 |
| 测试结论 | pass／fail／inconclusive | fail 为节点或配置失败，inconclusive 为无法可靠判定 |

当探测完整执行并确定节点不可达时，任务可以是 succeeded 且 verdict=fail；这不是任务系统故障。只有执行器故障、资源问题等才使用 failed 或 inconclusive，避免自动重试失效节点浪费流量。

# 7. 非功能需求与拟定指标

## 7.1 基准条件

以下是待验证的上线目标。建议基准环境为 Linux、4 vCPU、8 GiB 内存、SSD，API 与数据库在同机容器网络，Runner 使用独立资源配额。数据集为 10,000 节点、500 条链、200 组订阅和每方案不超过 10,000 条基础规则。负载测试关闭公网测速，以排除上游网络不确定性。

| 编号 | 指标／约束 | 验收方式 |
| --- | --- | --- |
| NFR-01 | 常规分页管理 API 的 P95 ≤500 ms；10 并发，20 分钟稳态 | 保存参数、数据集、错误率和延迟分布 |
| NFR-02 | 已发布订阅在 50 并发下 TTFB P95 ≤500 ms；1 MiB 产物 | 包含实时权限查询；不包含客户端公网传输时间 |
| NFR-03 | 500 个展开出站、2,000 条规则，纯编译 P95 ≤3 s | 不含内核检查、排队和联网测试 |
| NFR-04 | 同冻结输入的配置字节和摘要一致 | 重复编译至少 100 次并比较 |
| NFR-05 | 初始 Runner 连通性并发 4、吞吐并发 1 | 调度测试确认全局限额与本机限额都生效 |
| NFR-06 | 取消确认到子进程回收目标 ≤5 s；租约 30 s、心跳 5 s | 故障注入，不将停止过慢误报为已回收 |
| NFR-07 | 撤销提交后新请求不返回受影响字节 | 高频并发撤销测试；已开始的响应无法追溯撤回 |
| NFR-08 | 任何发布不得出现部分字节或混合目标版本 | 并发发布、断电模拟和请求对照 |
| NFR-09 | 密码、订阅令牌和完整配置不进入普通日志 | 自动秘密扫描及人工安全复核 |
| NFR-10 | 非特权运行，无公共测试代理端口 | 镜像与 Compose 静态检查、端口扫描 |
| NFR-11 | 备份基线 RPO ≤24 h，恢复演练目标 RTO ≤2 h | 依赖每日备份及演练；不是无条件可用性承诺 |
| NFR-12 | 核心解析／编译包语句覆盖率 ≥80%，关键不变量单独验证 | 覆盖率不替代正确性测试；正反样例和属性测试必须齐全 |
| NFR-13 | 三内核与两架构发布产物均有原生或等价环境烟测 | 仿真测试需标注，不能当作全部真实性能证据 |
| NFR-14 | 事件重连、任务恢复、日志限额均有自动化回归 | 断链、重启、超量日志和重复事件注入 |

## 7.2 默认限额

建议初始值：输入文本解码后 10 MiB、单批 5,000 条、单 URI 16 KiB、最多两层 Base64 解码；远程请求总超时 15 秒、重定向最多 3 次；单方案展开不超过 2,000 个出站、20,000 条内联规则及 10 MiB 配置。超限禁止静默截断。

测试默认单次连接 5 秒、单次 HTTP 请求 10 秒、配置检查 10 秒、内核启动 10 秒、任务总时限 60 秒。每个测试批次最多 100 个对象；每日测试预算初始 1 GiB，并同时登记协议开销不包含在应用层字节统计中的事实。部署者可根据资源调整，任何调整需要配置版本和审计记录。

# 8. 安全、隐私与数据治理

## 8.1 网络输入与执行边界

远程订阅、规则源、节点地址和测试目标都是不可信网络输入。来源抓取需要验证协议、域名解析、每次跳转及最终连接 IP，默认拒绝私网、回环、链路本地和元数据地址，防范 DNS 重绑定。仅做 URL 字符串校验不满足要求。[R16]

测试目标必须由管理员登记且预先校验，不提供任意 URL 测试接口。内核在线执行还需要网络级防护，不能只依赖 Go 抓取器的检查。第一跳地址能安全固定时固定到已校验 IP，并保留 SNI/Host 等语义；无法安全固定的组合默认不允许在线测试。更强的主机出站防火墙作为互联网开放部署前置条件。

## 8.2 秘密和凭证

账户密码与代理服务密码区别处理：账户密码只需要验证，应使用密码哈希；代理凭证需要在导出时还原，应加密存储。主密钥、令牌校验密钥与数据库分开保管，所有含凭证产物都属于敏感数据。[R17][R18]

管理页面禁止把真实令牌写入浏览器分析、错误上报、URL 引用信息和普通访问日志。未明确开启前，不接入第三方遥测。HTTPS 是公开部署的必要条件，不通过隐藏路径替代身份验证。

## 8.3 保留和删除

测试明细默认保存 30 天，脱敏任务日志 7 天，审计 180 天，原始导入内容 7 天，普通历史发布保留最近 20 个或 90 天。活动发布、备份恢复必需信息、被引用修订和正在运行任务不受普通清理规则直接删除。

被用户删除的节点先软删除；最终物理清理必须先做引用检查。秘密清理还应考虑备份中的旧副本，并提供轮换远端凭证的操作提示。

# 9. 页面信息架构与交互要求

| 页面 | 关键内容 | 主要操作与异常状态 |
| --- | --- | --- |
| 概览 | 节点数量、待发布变化、失败任务、内核状态 | 跳转问题对象；不显示伪造的用户流量 |
| 节点与来源 | 分页列表、协议标签、来源、兼容状态、历史测试 | 导入预览、覆盖标记、批量操作、引用影响 |
| 节点编辑 | 分协议字段、遮罩秘密、三内核能力 | 字段定位、版本冲突、未保存提示 |
| 代理链 | 有序两跳、出口、依赖、整体测试 | 交换方向、复用、故障不降级提示 |
| 策略组 | 策略、成员、默认项、目标差异 | 空组阻止保存；不支持策略有解释 |
| 路由与 DNS | 有序规则、默认出口、解析依赖 | 拖动排序、输入校验、循环提示 |
| 订阅方案 | 成员、自动依赖、目标、当前与待发布版本 | 编译预览、差异确认、发布、受控回滚 |
| 访问令牌 | 授权目标、到期、最近访问、撤销状态 | 签发时一次性展示，之后只能轮换 |
| 任务中心 | 阶段、进度、结论、位置、耗时、流量 | 取消、筛选、失败分层、事件重连 |
| 内核与系统 | 锁定版本、摘要、能力、限额、备份指引 | 停用、升级验证、密钥状态，不展示主密钥 |

默认配置预览为脱敏文本。所有敏感复制与导出明确区别于普通预览，使用后不保证能从用户剪贴板清除。任务被取消、来源变为 stale 和发布被 blocked 应使用不同提示，不统一显示“失败”。

# 10. 端到端验收用例

| 用例 | 前置与操作 | 必须观察到的结果 |
| --- | --- | --- |
| AC-01 | 初始化后尝试再次初始化、未认证调用管理 API | 初始化关闭；管理请求被拒绝 |
| AC-02 | 导入合法、重复、错误、未知协议混合列表 | 逐条诊断，预览无落库，确认后只保存选中有效项 |
| AC-03 | 导入含中文名称、IPv6、转义字符和缺失密码的 URI | 前三类正确解析；缺失认证失败，无默认密码 |
| AC-04 | 来源刷新改名和密码，且节点有人工名称覆盖 | 稳定 ID 保留，覆盖名称保留，凭证更新阻断旧发布 |
| AC-05 | 上游超时、空响应、身份模糊或节点消失 | 保留最近成功数据，冲突可见，消失项 stale |
| AC-06 | 两个编辑窗口提交不同修订 | 过期写返回冲突，已提交内容不被覆盖 |
| AC-07 | 创建 A→B，再创建 A→C，并独立使用 B | 原节点不变；链实例互不影响 |
| AC-08 | 创建 A→A、三跳或 TCP 第一跳承载不支持的 UDP 末跳 | 静态校验拒绝并指出原因 |
| AC-09 | 受控环境使 B 只允许来自 A 的连接，再测试 A→B | 完整链成功；绕过 A 的反例失败，确认连接方向 |
| AC-10 | 停止第一跳或使所有策略成员失效 | 请求失败；本机直连出口没有意外目标流量 |
| AC-11 | 对 sing-box 目标使用未适配的 round_robin | 报不支持；不会自动变为 urltest |
| AC-12 | 设置顺序域名/CIDR规则及解析依赖循环 | 顺序命中符合定义；DNS 循环被阻止 |
| AC-13 | 两组订阅不同成员，一组包含链，显式排除链依赖 | 正常组依赖齐全；冲突组无法发布 |
| AC-14 | 某目标配置检查失败且已有旧发布 | 新批次失败；安全有效的旧发布继续服务 |
| AC-15 | 编译期间修改节点或标签筛选结果 | 编译变为 obsolete，禁止覆盖新状态 |
| AC-16 | 并发下载时发布或撤销令牌 | 发布切换无混合；撤销提交后新请求无配置字节 |
| AC-17 | 旧发布依赖的节点停用、改凭证，再尝试回滚 | 下载受阻，安全状态不允许的历史版本不能恢复 |
| AC-18 | 三内核分别做配置检查、HTTP 探测和限额下载 | 配置与网络结论分离，指标包含版本和位置 |
| AC-19 | 批量测速达到字节预算、取消、Runner 失联 | 停止任务、清理进程；旧租约不能覆盖结果 |
| AC-20 | 来源和节点地址指向私网、重绑定或恶意重定向 | 抓取与内核执行均被相应安全层阻断 |
| AC-21 | 干净主机部署、重启、升级并回退兼容镜像 | 数据持久、健康检查有效、无公共测试代理 |
| AC-22 | 从旧备份恢复，包括旧的有效令牌和 running 任务 | 旧凭证默认失效；任务不自动重复测速；节点可解密 |
| AC-23 | 扫描数据库、日志、SSE、审计和错误页 | 不出现明文秘密及完整订阅 URL |
| AC-24 | 500 出站编译及规定规模的接口压力测试 | 记录实测值并与 NFR 对照，不以估计代替结果 |

## 11.3 上线前需要确认但已有默认值的事项

内核的精确版本、构建摘要和客户端名称必须在 M0 冻结；本文不虚构已安装或已验证的版本。团队应明确实际机器容量、测试目标与预算、备份保管人，以及是否仅对可信管理员开放。未作新决定时，按第 2、7、8 章默认值执行，不影响按此文档开始设计和实现。

数据库选型、双跳限制、严格发布、无自动直连、单工作空间和独立 Runner 已作为本基线确定的设计输入；变更这些事项必须同步更新两份文档及验收用例。
